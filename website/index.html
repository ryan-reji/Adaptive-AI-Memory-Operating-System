What it does

Everything you've worked on,
searchable in seconds.

Recall passively captures your activity and builds a personal, searchable memory — no cloud, no tracking.

🌐

Browser Activity

Captures pages you visit in Chrome, Brave, and Edge. Filters out irrelevant content automatically.

💻

VS Code Activity

Tracks files and projects you edit in VS Code — tied to your permission settings, not a separate system.

📁

File Activity

Monitors folders you allow, capturing file reads and edits. Protected system locations are always blocked.

🧠

AI Relevance Filter

Uses a local Ollama LLM to classify each activity as relevant, uncertain, or irrelevant before storing.

🔍

Semantic Search

Ask anything about your past work in natural language. Powered by embeddings and RAG — all local.

🗑

Smart Forgetting

A Random Forest model flags stale files for review. You decide what stays — nothing is ever auto-deleted.

Under the hood

How Recall works

01

Activity monitoring starts automatically

When you open Recall, the orchestrator starts monitoring your browser, VS Code, and permitted folders in the background.

02

Every 60 seconds — relevance classification

Captured activity is sent to a local LLM (qwen3.5:4b via Ollama) which decides if each item is worth remembering.

03

Relevant items become memories

Relevant and uncertain items are stored as memory records in a local SQLite database — irrelevant activity is discarded.

04

Embeddings → ChromaDB → RAG

Memories are chunked, embedded with sentence-transformers, and stored in ChromaDB for semantic retrieval.

05

Ask anything

Use the Search page to ask natural language questions. The RAG pipeline retrieves relevant memories and generates a grounded answer.

🛡

Everything stays on your device

No data leaves your machine. The LLM runs locally via Ollama, embeddings are stored locally in ChromaDB, and all databases live in your user profile. No accounts, no cloud sync, no telemetry.
